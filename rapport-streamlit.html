Introduction et Contexte

1.1 Problématique

Les entreprises tunisiennes reçoivent quotidiennement des centaines de commentaires clients sur leurs réseaux sociaux (Facebook, Instagram), rédigés dans un mélange unique de dialecte tunisien (Derja), d'Arabizi (arabe translittéré en caractères latins avec chiffres), de français et d'arabe standard. Cette réalité linguistique rend l'analyse manuelle impossible à grande échelle et les outils standard de NLP inadaptés.

💡 Problème central
Comment extraire automatiquement la satisfaction client depuis des données textuelles tunisiennes multilingues non structurées, et la restituer sous forme de tableau de bord actionnable pour n'importe quelle entreprise ?

1.2 Objectifs du PFE

  1. Construire un pipeline NLP complet capable de traiter du texte tunisien quelle que soit sa langue (arabe, arabizi, français, anglais)
  2. Déployer un modèle de classification de sentiment adapté au dialecte tunisien — 3 classes : positif / négatif / neutre
  3. Intégrer un module d'explicabilité (LIME) pour justifier chaque prédiction du modèle
  4. Livrer une application web générique où n'importe quelle entreprise peut uploader ses données et obtenir un dashboard d'analyse en temps réel

Modèle de Sentiment — MARBERT

3.1 Choix du modèle

MARBERT (Multi-Dialect Arabic BERT) est un modèle Transformer pré-entraîné par le CAMeL Lab sur 1 milliard de tweets arabes dialectaux incluant des variantes tunisiennes, égyptiennes, marocaines et du Golfe. Il a été sélectionné pour sa capacité native à traiter l'arabe dialectal sans prétraitement supplémentaire.

3.2 Fine-tuning

Le modèle a été fine-tuné sur un dataset annoté de commentaires tunisiens avec une étape spéciale de génération de données neutres pour rééquilibrer les classes :

📌 Note sur le suffixe "-balanced-after-gen-neut"
La classe neutre est naturellement sous-représentée dans les commentaires clients. Une étape de génération de données neutres synthétiques a été ajoutée pendant l'entraînement pour équilibrer les 3 classes et éviter le biais vers les sentiments extrêmes.

def should_keep(text):
    if has_no_real_content(text):  return False  # ni arabe ni latin
    if has_gibberish_latin(text):  return False  # ≥ 7 consonnes consécutives
    if is_gibberish_random(text):  return False  # mot 15+ chars sans voyelle
    if has_high_char_repeat(text): return False  # 1 char > 28% du texte
    if has_repetitive_words(text): return False  # 1 mot > 45% des mots

Pipeline de Traitement

5.1 Détection de Langue

La détection opère en cascade de priorité décroissante :

def detect_language(text):
    # 1. Ratio caractères arabes > 25% → arabic (envoi direct à MARBERT)
    if arabic_chars / total_chars > 0.25:
        return 'arabic'

    # 2. Score Arabizi (chiffres-lettres tunisiens + lexique)
    score  = occurrences([3,7,9]) × 2   # 3=ع  7=ح  9=ق  (marqueurs forts)
    score += occurrences([4,8])          # 4=غ  8=   (marqueurs modérés)
    score += mots_tunisiens_reconnus × 3 # barcha, mriguel, kifech...
    if score >= 3: return 'arabizi'

    # 3. langdetect (bibliothèque) pour français/anglais
    lang = langdetect.detect(text)
    if lang == 'fr': return 'french'
    if lang == 'en': return 'english'

    return 'arabizi'  # défaut sécurisé → MARBERT le gère

Le lexique Arabizi tunisien contient 50+ mots caractéristiques : barcha, mriguel, kifech, shkoun, wesh, bahi, brabi, sahbi, inchallah, mabrouk…

5.2 Traduction Groq API

Les 432 textes français et anglais (16.7%) sont traduits en arabe avant la prédiction. La traduction utilise Llama-3.3-70B-Versatile via l'API Groq avec un prompt zéro-shot :

"Traduis ce texte en arabe. Réponds uniquement avec la traduction arabe,
sans explication. Texte : {text}"

Un délai de 300ms entre chaque appel respecte les limites de débit. En cas d'échec de l'API, le texte original est transmis à MARBERT (fallback gracieux).

5.3 Prédiction MARBERT en Batch

Les textes sont traités en batches de 32 pour optimiser l'utilisation du GPU :

def predict_batch(texts, tokenizer, model, device):
    enc = tokenizer(
        texts, return_tensors='pt',
        padding=True, truncation=True, max_length=128
    ).to(device)
    with torch.no_grad():
        logits = model(**enc).logits
    return softmax(logits, dim=-1).numpy()  # shape (N, 3)

Le script run_predictions.py implémente un système de checkpoint : sauvegarde automatique tous les 200 textes dans le CSV de sortie. Si le processus est interrompu, il reprend à l'index où il s'était arrêté.

Explicabilité — LIME

6.1 Principe de LIME

LIME (Local Interpretable Model-Agnostic Explanations) génère des explications locales en perturbant aléatoirement le texte d'entrée (masquage de mots) et en observant l'impact sur les probabilités de prédiction. Il entraîne un modèle linéaire local (interprétable) pour approximer le comportement du modèle noir (MARBERT) autour de ce texte spécifique.

ParamètreValeur choisieJustification
bow=FalseDésactivéPréserve l'ordre des mots — crucial pour l'arabe
num_samples500Équilibre précision / temps de calcul
num_features10Top 10 mots influents par classe
labels[0, 1, 2]Explication pour les 3 classes simultanément

6.2 Lecture des résultats LIME

Pour chaque texte analysé, 3 graphiques horizontaux sont affichés (un par classe) :

  • Barres colorées (couleur du sentiment) → mots qui poussent vers cette classe
  • Barres grises → mots qui s'opposent à cette classe
  • La classe prédite est marquée "← PRÉDIT"
🎯 Valeur pour la soutenance
LIME permet de répondre à la question du jury : "Comment le modèle prend-il sa décision ?". C'est ce qui différencie ce PFE d'un simple classifieur boîte noire — l'explicabilité est une exigence croissante en IA responsable (EU AI Act).

7.2 Fonctionnalités par page

📈 Vue Globale

  • 5 KPIs : total, %positif, %négatif, %neutre, NSS (Net Sentiment Score = (pos−neg)/total×100)
  • Donut chart de répartition des sentiments
  • Bar chart des langues détectées
  • Histogramme de confiance du modèle
  • Top 15 mots par sentiment — négatif / positif / neutre (graphiques horizontaux)
  • Graphique miroir — mots exclusivement positifs vs exclusivement négatifs

🔍 Analyse Détaillée

  • Top 5 exemples par sentiment, triés par confiance décroissante
  • Cartes colorées adaptées au thème (light/dark/system)
  • Tableau filtrable avec toutes les colonnes
  • Export CSV des résultats filtrés

🔬 LIME Explorer

  • Mode 1 : sélectionner un commentaire depuis les résultats
  • Mode 2 : saisir un texte libre (traduit automatiquement si fr/en)
  • Calcul LIME (~20 secondes) avec 3 graphiques d'importance

📁 Données

  • Tableau complet (id, text, langue, texte_marbert, sentiment, confiance, prob_neg, prob_neu, prob_pos)
  • Export CSV et JSON en un clic

8.3 Limites identifiées

LimitationExempleImpact
Arabizi positif mal classé "Service client yraddou... mrigul" → NEGATIF Moyen
Sarcasme non détecté "Bravo topnet 😒" → POSITIF Faible
Contexte vs mot clé "C'est dommage, l'app kenet a7la" → POSITIF (a7la=beau en arabe) Faible
Textes trop courts "👍" ou "top" → confiance faible (<70%) Faible
⚠️ Contexte de ces erreurs
Ces erreurs sont attendues et normales pour un modèle traitant de l'Arabizi — dialecte parmi les plus difficiles en NLP. Même les modèles commerciaux (GPT-4, Azure Cognitive Services) produisent des erreurs similaires sur le tunisien. Les 8.4% de prédictions à faible confiance sont précisément les cas où le modèle signale lui-même son incertitude.

Conclusion

Bilan du projet

Ce projet a permis de construire un système complet d'analyse de sentiment adapté à la réalité linguistique tunisienne, de la collecte des données brutes jusqu'au tableau de bord interactif. Le pipeline automatisé — nettoyage, détection de langue, traduction, classification MARBERT, explicabilité LIME — traite 2 581 commentaires avec une confiance moyenne de 93% et se présente au travers d'une application Streamlit entièrement générique, réutilisable par n'importe quelle entreprise tunisienne sans modifier une ligne de code.

La valeur technique du projet réside dans la maîtrise de trois défis simultanés : le multilinguisme (arabe / arabizi / français / anglais dans un même dataset), l'explicabilité (LIME justifie chaque décision du modèle), et la généricité (architecture pipeline-as-a-service applicable à tout secteur).
